      - 会计报销场景（第12页）：财务系统→三单合一自动归档
      - 项目工程场景（第13页）：项目系统→预立卷自动归档
  V2_predictive_power:
    passed: true
    novel_question: "一个新上线的采购管理系统，如何接入档案系统实现自动归档？"
    derived_answer: |
      按照业档一体框架，步骤是：
      1. 梳理采购业务的归档范围和保管期限表（哪些文件需要归档、存多久）
      2. 定义采购档案的元数据字段和门类
      3. 通过集成引擎建立字段映射（业务系统字段→档案系统元数据）
      4. 在采购流程办结节点触发归档动作
      5. 档案系统接收后执行四性检测，自动分类组件
      6. 档案数据反向可被采购系统安全调用（如查历史合同）
  V3_exclusivity:
    passed: true
    why_not_common: |
      常识认为"档案管理是后端的事，业务系统管业务，档案系统管档案，最后导一份数据过去就行"。
      业档一体是反直觉的——它要求业务流程和档案流程从设计阶段就深度融合，
      不是"数据搬运"而是"流程一体化"，且强调档案数据反哺业务的双向价值。

- id: f03
  title: 预归档平台方法论
  type: framework
  V1_cross_domain:
    passed: true
    evidence:
      - 预归档管理章节（第20页）：专门的功能模块介绍
      - 核心亮点章节（第49页）：预归档平台是十二大亮点之一
      - 业档一体架构（第14页）：预归档是业务系统与档案系统之间的中间层
      - 项目工程场景（第13页）：预立卷机制就是预归档的具体应用
  V2_predictive_power:
    passed: true
    novel_question: "为什么中小企业只有一个档案员，但档案工作总是做不完？"
    derived_answer: |
      用预归档方法论分析，问题出在"单兵作战"模式：
      1. 所有档案工作压在档案员一人身上，前端业务人员不参与
      2. 档案员不了解业务背景，整理时需要反复确认，效率低
      3. 文件容易遗漏，档案完整性差
      解法：建立预归档机制，让各部门兼职档案员在前端完成预整理，
      档案员只负责审核和正式归档，从"1人干100人的活"变成"100人各干一点+1人审核"。
  V3_exclusivity:
    passed: true
    why_not_common: |
      常识认为"档案是档案员的事，业务人员不懂档案也不应该管"。
      预归档方法论是反直觉的——它主张"收集整理前置化"，
      让最懂业务的人在产生数据时就参与预整理，档案员从"操作员"变成"审核员"，
      效率和质量反而更高。这是组织分工上的反常识洞见。

- id: f04
  title: 四性检测框架
  type: framework
  V1_cross_domain:
    passed: true
    evidence:
      - 档案收集章节（第28页）：专门的四性检测功能模块
      - 数字防篡改亮点（第47页）：四性检测+电子签名构成防篡改体系
      - 公文业档一体场景（第9页）：接收环节执行四性检测
      - 档案移交章节（第33页）：移交接收环节需要合规检测
  V2_predictive_power:
    passed: true
    novel_question: "电子档案怎样才能在法庭上作为证据使用？"
    derived_answer: |
      按四性检测框架，需要确保：
      1. 真实性——有电子签名/时间戳，能证明档案内容未被篡改、来源可信
      2. 完整性——元数据齐全、附件完整、没有缺页漏项
      3. 安全性——存储过程有加密、有备份、有访问控制，未被未授权访问
      4. 可用性——文件格式可正常读取、内容可正常显示
      同时，这四项检测需要在三个关键节点执行：接收时、归档时、长期保存定期检测，
      形成完整的证据链，才能在法律上站得住脚。
  V3_exclusivity:
    passed: true
    why_not_common: |
      常识认为"电子档案存好就行，文件不坏就能用"。
      四性检测框架揭示了电子档案要具备法律效力，
      不是"存起来"这么简单，而是需要从真实、完整、安全、可用四个维度系统性保障，
      且需要在全生命周期多个节点持续检测。这是档案专业领域的深度知识。

- id: f05
  title: 分级分权权限管理框架
  type: framework
  V1_cross_domain:
    passed: true
    evidence:
      - 核心亮点章节（第51页）：分级分权是十二大亮点之一
      - 后台配置章节（第43页）：全宗管理+分类赋权是档案设置的核心
      - 系统设置章节（第44页）：组织/用户/角色/权限多层管理
      - 四类整编模式（第22页）：不同管理模式对应不同权限配置
  V2_predictive_power:
    passed: true
    novel_question: "集团型企业有多个子公司，每个子公司都有自己的档案，如何设计权限体系？"
    derived_answer: |
      按分级分权框架设计：
      1. 按全宗划分——每个子公司是一个独立全宗，数据天然隔离
      2. 按门类组合权限——不同全宗下可以有不同的档案门类，权限按门类组合
      3. 多维度授权——组织权限（哪个全宗）+角色权限（什么角色）+功能权限（哪些菜单）+数据权限（哪些数据）
      4. 快速赋权——先按门类定义权限模板，关联全宗后批量授予用户/角色
      5. 流程权限——借阅、鉴定、销毁等审批流程单独配置节点权限
  V3_exclusivity:
    passed: true
    why_not_common: |
      常识认为"权限就是管理员和普通用户两种"，或者按角色分配功能权限。
      分级分权框架的独特之处在于"全宗+门类"作为权限的基本组织单元，
      不是简单的RBAC（角色-权限），而是"全宗-门类-组织-角色-功能-数据"六维组合，
      这是档案领域因应集团型多级组织管理需求发展出的特定方法论。

- id: f06
  title: 双套制向单套制过渡框架
  type: framework
  V1_cross_domain:
    passed: true
    evidence:
      - 背景概述章节（第6页）：双套制向单套制过渡是解决方案的核心命题
      - 政策驱动章节（第5页）：《电子档案单套管理一般要求》提供了政策依据
      - 符合国标亮点（第57页）：支持国标/行标/地方标准的归档数据包
      - 档案移交章节（第33页）：EEP数据包是单套制移交的标准格式
  V2_predictive_power:
    passed: true
    novel_question: "一家传统制造企业，目前还是纸质档案为主，想逐步推进数字化，应该怎么规划？"
    derived_answer: |
      按双套制向单套制过渡框架，分三步走：
      第一步（双套制并行）：现有纸质档案数字化加工，新产生的电子文件开始预归档，两套并行管理，库房管纸质、系统管电子
      第二步（逐步过渡）：选择成熟的业务领域（如公文、合同）先行试点单套制，
        用电子签章+四性检测保障电子档案法律效力，逐步减少纸质打印和归档
      第三步（全面单套制）：各门类陆续实现单套制，纸质仅作为特殊情况的补充，
        电子档案成为主要甚至唯一的管理对象
      注意：过渡节奏取决于企业信息化成熟度、政策要求、风险承受能力，不能一刀切。
  V3_exclusivity:
    passed: true
    why_not_common: |
      常识认为"要数字化就一步到位，全部电子化"，或者"纸质最保险，不能丢"。
      双套制向单套制过渡框架的独特之处在于它承认"过渡是一个过程"，
      不是非黑即白的选择，而是可以分阶段、分门类、分风险等级逐步推进，
      同时有明确的过渡路径和支撑要素（电子签章、四性检测、标准数据包）。

- id: f07
  title: 档案利用控制框架
  type: framework
  V1_cross_domain:
    passed: true
    evidence:
      - 档案借阅章节（第38页）：借阅流程和权限控制
      - 利用控制章节（第39页）：原文遮盖和页码控制
      - 档案编研章节（第40页）：档案的深度利用和价值挖掘
      - 分级分权框架（第51页）：数据权限是利用控制的基础
  V2_predictive_power:
    passed: true
    novel_question: "企业的涉密合同档案，如何在保障安全的前提下让业务部门能查阅需要的部分？"
    derived_answer: |
      按档案利用控制框架，分四层管控：
      1. 检索层——涉密档案默认不在普通检索结果中显示，需特定权限才能搜到
      2. 借阅层——必须走审批流程，说明用途和期限，审批通过才能看
      3. 操作层——只允许预览，不允许下载和打印，加上动态水印防止截屏
      4. 内容层——使用原文遮盖功能，把合同中不需要的敏感信息（如金额、对方联系方式）涂抹掉，
        只生成包含必要内容的借阅副本，还可以控制只开放指定页码
      时间维度：设置借阅期限，到期自动收回权限
  V3_exclusivity:
    passed: true
    why_not_common: |
      常识认为"信息安全就是'能看'和'不能看'两种，非黑即白"。
      档案利用控制框架的独特之处在于它提供了"灰度控制"的多层次手段——
      从能不能搜到，到能不能申请，到能做什么操作，到能看到多少内容，
      每一层都有独立的控制手段，实现了"安全"和"利用"之间的平衡。
      这不是简单的权限管理，而是精细化的信息访问控制方法论。
