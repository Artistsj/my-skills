# 档案管理（文书定）-解决方案-综合档案-预归档平台方法论

## R — 原文 (Reading)

> "按照业务场景进行文件划分，从单兵作战向系统作战演进。收集整理前置化：
> 对于归档周期较长、自动分类规则不明确的档案，可预先进入预归档库，
> 由兼职档案管理员或部门业务人员进行日常维护，保证档案完整性。
> 业档融合深度化：设置预归档库中与接收库中的元数据字段映射关系，
> 可进行批量组件、合并组件操作，并进行自动分类。"
>
> — 泛微文书定，第49页·核心亮点·预归档平台

---

## I — 方法论骨架 (Interpretation)

预归档的核心洞见是：**档案收集整理工作不应该全部压在后端档案员身上，而应该尽可能前置到业务端，让最懂业务的人参与进来**。

传统模式是"单兵作战"——业务部门产生文件，攒一批交给档案员，档案员一个人整理、分类、著录、组卷。但档案员不了解业务背景，整理效率低、容易出错，文件也容易遗漏。

预归档模式是"系统作战"——在业务系统和正式档案库之间建立一个缓冲层（预归档库）：
- 第一层：业务人员产生文件时，就在前端进行初步整理
- 第二层：各部门兼职档案员在预归档库中进行预整理（元数据完善、档案分类、组件）
- 第三层：专职档案员审核后，一键正式归档

通过"收集整理前置化 + 三级协作体系"，实现从"1个人干100份活"到"100个人各干一点+1个人审核"的转变，效率和质量同时提升。

## A1 — 书中的应用 (Past Application)

### 案例 1: 项目工程档案预立卷
- **问题**: 工程项目周期长、参与方多、文件量大，项目结束后集中整理档案非常困难，经常缺件漏项
- **方法论的使用**: 在项目进行过程中，通过预归档平台基于收集保管范围表实时预立卷，各参建方的文件随时上传、随时整理，项目竣工验收后直接审核归档
- **结论**: 把档案整理工作分散到项目全周期中，而不是等到结束后集中处理
- **结果**: 项目档案完整性大大提高，归档速度加快，避免事后补资料

### 案例 2: 四类整编模式适配不同组织
- **问题**: 不同企业的档案管理组织模式差异很大，有的只有1个档案员，有的有完整团队
- **方法论的使用**: 基于预归档思路设计了四种整编模式：单人模式（无预归档，直接入库）、多人模式（档案室内部协作）、兼职汇总模式（兼职档案员预整理+档案员二次整编）、部门独立模式（各部门自行整编归档）
- **结论**: 预归档的深度要与组织模式匹配，不是所有企业都需要三级协作
- **结果**: 不同规模和组织模式的企业都能找到适合自己的收集整理方式

### 案例 3: 看图著录收集方式
- **问题**: 对于图片、扫描件等非结构化文件，档案员需要一边看图一边录入元数据，效率低且容易看错
- **方法论的使用**: 支持"无条目看图著录"——上传文件后，在预览界面框选文字内容，通过OCR自动提取填充著录字段，由兼职档案员或业务人员在前端完成
- **结论**: 利用技术手段降低前端预整理的门槛，让非专业人员也能做著录
- **结果**: 著录效率提升，同时因为是产生文件的人自己录入，准确性更高

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 档案员抱怨工作量太大、做不完，需要提升档案收集整理效率时
2. 档案完整性差，经常出现"应该归档但没归档"的情况，需要解决时
3. 企业想让业务部门也参与档案工作，但不知道怎么设计协作机制时
4. 规划档案管理系统中的"预归档"功能模块时
5. 讨论"档案管理组织模式"、"兼职档案员怎么用"这类问题时

### 语言信号 (用户的话里出现这些就应激活)

- "预归档" / "预归档库" / "预立卷"
- "收集前置化" / "整理前置"
- "兼职档案员" / "部门档案员"
- "单兵作战" / "系统作战"
- "档案员太忙了" / "档案收集不完"
- "档案总是缺件" / "完整性差"

### 与相邻 skill 的区分

- 与 `archives-yidang-yiti` 的区别：预归档是业档一体架构中的一个具体机制（缓冲层），回答"怎么让业务端参与归档"；业档一体是整体架构，回答"业务和档案怎么融合"
- 与 `archives-lifecycle` 的区别：预归档是"收"这个阶段中的一个子方法；全生命周期覆盖收管存用四个阶段
- 与 `archives-permissions` 的区别：分级分权讲的是权限控制体系；预归档讲的是工作分工和流程前置，虽然涉及角色，但核心是效率和质量

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **评估当前档案收集模式的痛点**
   - 完成标准：明确当前痛点是什么——是效率低？是完整性差？是整理质量差？还是档案员超负荷？
   - 判停条件：若痛点不明确，先做现状调研

2. **设计三级协作体系**
   - 完成标准：明确三个角色的职责分工
     - 业务人员：产生文件、初步上传
     - 兼职档案员：预整理（完善元数据、分类、组件）
     - 专职档案员：审核、正式归档
   - 判停条件：若企业规模小，只有一个档案员，可跳过兼职档案员层级

3. **规划预归档库的功能**
   - 完成标准：明确预归档库需要支持的功能——元数据自动转换、档案预整理、档案类型匹配、自动分类、自动组件、自动关联

4. **定义从预归档到正式归档的流转规则**
   - 完成标准：明确什么情况下可以从预归档库正式归档、谁来审核、审核通过的标准是什么

5. **设计配套的管理制度**
   - 完成标准：制定兼职档案员管理制度、预归档工作规范、考核激励机制
   - 关键提醒：预归档不只是技术问题，更是组织管理问题，制度配套是成功关键

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 企业完全没有信息化基础，连档案系统都没有——预归档需要系统支撑
- 档案量很小（比如一年几十份），不值得建立三级协作体系
- 已正式归档后的档案管理问题——预归档只解决"收"的阶段

### 作者在书中警告的失败模式

- "单兵作战"模式：所有档案工作都压在专职档案员身上，效率低、易出错、完整性差
- 业务部门觉得"归档是档案员的事"，没有参与意识，导致档案收集被动

### 作者的盲点 / 时代局限

- 假设企业愿意投入人力做兼职档案员，但实际中很多企业业务部门自己都忙不过来
- 对人的因素考虑不足：兼职档案员的积极性、专业性、流动性都是问题，不是光靠系统能解决的
- 作者是产品厂商，倾向于"用系统解决问题"，但预归档的成功更多取决于管理制度和组织文化

### 容易混淆的邻近方法论

- 不要和"工作流审批"混淆：预归档不是简单的多级审批，而是把整理工作本身分散到前端
- 不要和"内容协作平台"混淆：预归档有明确的档案管理目标（分类、组件、归档），不是通用的文档协作
