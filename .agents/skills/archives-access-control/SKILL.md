# 档案管理（文书定）-解决方案-综合档案-档案利用控制框架

## R — 原文 (Reading)

> "电子借阅可限制其预览、下载、打印权限并配置动态水印，到期自动收回权限；
> 实体借阅自动生成出入库单，出库自动盘点。通过借阅流程进行档案的在线审批，
> 系统支持在审批流程中对原文进行遮盖处理后生成【借阅副本】，
> 遮盖时支持对内容涂抹、加入文本、上传图片等操作；
> 支持在借阅时对页码控制，只开放指定页码。"
>
> — 泛微文书定，第38页·档案借阅 / 第39页·利用控制

---

## I — 方法论骨架 (Interpretation)

档案利用不是"要么全看、要么不看"的二元选择，而是一个多层次、细粒度的控制体系。通过从粗到细的四层控制，可以在保障安全的前提下最大化档案的利用价值。

**四层控制体系：**

第一层 **检索控制**——能不能搜到。敏感档案默认不在普通检索结果中显示，需要特定权限或特定检索入口才能搜到。这是最外层的控制。

第二层 **借阅控制**——能不能看。查阅档案需要走审批流程，说明用途、期限、范围，审批通过后才能获得访问权限。这是流程层的控制。

第三层 **操作控制**——能做什么操作。即使获得了借阅权限，还可以细分为：只能预览 / 可以下载 / 可以打印，以及是否允许复制等。加上动态水印防止截屏外传。这是功能层的控制。

第四层 **内容控制**——能看到多少内容。这是最细粒度的控制：原文遮盖（涂抹掉敏感信息）、页码范围控制（只开放指定页码）、生成借阅副本（不是原文本身）。这是内容层的控制。

**两个补充维度：**
- **时间维度**：借阅有期限，到期自动收回权限
- **形式维度**：电子借阅 + 实体借阅（自动生成出入库单、出库自动盘点）

核心思想：**安全和利用不是对立的，而是可以通过多层次控制实现平衡——让合适的人、在合适的时间、以合适的方式、看到合适的内容。**

## A1 — 书中的应用 (Past Application)

### 案例 1: 涉密合同的分级查阅
- **问题**: 合同档案包含敏感信息（金额、对方联系方式、核心条款），但业务部门又需要查阅合同作为参考，怎么平衡？
- **方法论的使用**: 四层控制全用上——检索层：涉密合同默认不显示在普通检索中；借阅层：必须走审批流程；操作层：只允许预览，不能下载打印，加动态水印；内容层：用原文遮盖涂抹掉敏感信息，只开放必要的内容和页码
- **结论**: 通过多层次控制，既满足了业务部门的查阅需求，又保护了敏感信息
- **结果**: 安全和利用实现平衡，而不是非黑即白

### 案例 2: 电子借阅到期自动收回
- **问题**: 传统方式下，档案借出去了就不知道什么时候还，经常逾期不还，甚至丢失
- **方法论的使用**: 电子借阅设置借阅期限，到期系统自动收回权限；借阅期间的操作都有日志记录；动态水印显示借阅人信息，防止截屏泄露
- **结论**: 时间维度的控制是利用控制的重要一环
- **结果**: 借阅全程可控、可追溯，到期自动归还，无需人工催还

### 案例 3: 档案编研——从"存"到"用"的价值挖掘
- **问题**: 档案只用来备查太可惜了，怎么发掘更大价值？
- **方法论的使用**: 在保障安全的前提下，通过编研功能对档案进行二次开发——形成大事记、组织沿革、基础数字汇编、专题研究等编研成果，让档案数据更好地融入业务
- **结论**: 利用控制的目的不是限制利用，而是在安全的前提下最大化利用价值
- **结果**: 档案从"保管对象"变成"价值资产"

### 与相邻 skill 的区分

- 与 `archives-permissions` 的区别：分级分权是整体权限体系的架构设计（谁管什么范围、有什么功能权限）；利用控制是"利用"环节的精细化访问控制（从检索到内容的四层控制），更聚焦、更细粒度
- 与 `archives-lifecycle` 的区别：全生命周期覆盖收管存用四个阶段；利用控制只是"用"这个阶段中的一个子方法
- 与 `archives-four-tests` 的区别：四性检测的"安全性"是指档案本身不被篡改、不丢失；利用控制的"安全"是指访问控制，防止未授权查阅

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **评估档案的敏感等级分类**
   - 完成标准：按敏感程度对档案门类进行分级（如：公开/内部/秘密/机密），不同等级对应不同的控制强度
   - 判停条件：若没有敏感等级分类，先做分级

2. **设计第一层：检索控制**
   - 完成标准：明确哪些档案在普通检索中可见、哪些需要特定权限、哪些完全不可检索
   - 关键原则：越敏感的档案，检索可见范围越小

3. **设计第二层：借阅控制**
   - 完成标准：设计借阅审批流程——谁可以发起、需要谁审批、审批要素（用途、期限、范围）、审批通过后的权限生效方式

4. **设计第三层：操作控制**
   - 完成标准：定义不同角色/不同敏感等级档案对应的操作权限——预览/下载/打印/复制，以及动态水印策略

5. **设计第四层：内容控制**
   - 完成标准：明确原文遮盖的使用场景、遮盖方式（涂抹/加文本/加图片）、页码控制规则、借阅副本生成机制

6. **补充时间维度和形式维度**
   - 完成标准：设计借阅期限机制、到期自动收回规则、实体借阅流程

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯系统安全问题（如防火墙、入侵检测、数据加密存储）——这是IT安全范畴
- 整体权限体系设计——用分级分权框架更合适
- 档案完全公开、没有敏感内容的场景——不需要这么多层次的控制

### 作者在书中警告的失败模式

- "重保管、轻利用"——为了安全干脆不让用，导致档案价值无法体现，档案部门逐渐边缘化
- 权限控制太粗——要么全看、要么不看，没有中间地带，无法平衡安全和利用
- 借阅失控——档案借出去就不管了，逾期不还、私自复印、信息泄露

### 作者的盲点 / 时代局限

- 作者是产品厂商，倾向于"技术手段能解决一切"，但实际中利用控制的效果很大程度上取决于管理制度和人员意识
- 对"合理使用"的边界讨论不足——什么情况下应该允许利用、什么情况下应该限制，更多是管理制度问题，不是技术能完全界定的
- 原文遮盖在实际应用中可能有局限性——对于结构化数据、表格等内容，涂抹可能破坏信息完整性，实际效果打折扣

### 容易混淆的邻近方法论

- 不要和"数据防泄漏（DLP）"混淆：利用控制是档案管理领域的业务控制，关注的是档案利用过程中的权限和内容控制；DLP是技术安全产品，关注的是数据流出企业的防护
- 不要和"数字版权管理（DRM）"混淆：DRM主要针对音视频等数字内容的版权保护；利用控制是档案业务管理的一部分，范围更广
